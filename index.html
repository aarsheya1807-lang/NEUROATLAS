Design & build notes

Why this module is built the way it is.

Data model Every mode reads from one shared array (REGIONS) instead of maintaining separate copies. Add a region once — DSM-5-TR code, ICD-11 code, function, deficits — and it's automatically available in Explore, Reverse Diagnosis, Lesion Stacking, and Split Compare.
Why in-memory state, not localStorage Scores, streaks, and calibration history live in a JS object for this session only. If you want persistence across visits, use the site's proper storage layer (a small backend, or the artifact/app storage API) rather than browser storage, which isn't reliable across all embedding contexts.
Confidence calibration Before revealing the answer in Reverse Diagnosis and Timed Triage, we ask "how confident are you?" (0–100%). Over many rounds we bucket guesses by confidence and plot accuracy per bucket — a well-calibrated user should be right ~70% of the time when they said "70% confident."
Accessibility mode Swaps the signal/lesion palette to a colorblind-safer blue/amber pairing (avoids red-green reliance) and is meant to sit alongside — not replace — full keyboard navigation, which every chip/tab already supports via native button elements and visible focus rings.
What's sample data vs. what you own The 10 regions and 4 historical cases here are placeholders with real, sourced clinical information — but you should replace them with your existing 20-region dataset and cite your actual references (DSM-5-TR, ICD-11, a neuroanatomy text) in a visible sources section.
